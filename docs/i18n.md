# Localization (game terms + chrome)

**Status:** hard truth  
**Cursor stub:** [`.cursor/rules/i18n.mdc`](../.cursor/rules/i18n.mdc)  
**Sources:** AD-005, AD-006; features `english-game-terms`, `portuguese-ux-copy`

## Language policy

1. **UI chrome** is bilingual via `src/shared/i18n` (`Lang = 'pt' | 'en'`). Default remains `pt` unless product changes it.
2. **Game terms follow `Lang`.** When `Lang === 'en'`, abilities, ability effect text, hero/item rarities, houses, slots, sheet/team-buff labels, props, equipment set names, and composed item display labels are English. When `Lang === 'pt'`, show Portuguese (official in-game names for abilities/houses where applicable; natural PT for set names).
3. **Internal IDs/keys stay PT-key stable** — do not rename storage/schema keys (`Comum`, `ponta_diamante`, slot `arma`, prop `minerio_mithril`, set slug `clay`, …). Localization is display-layer only.
4. **Display maps** live in `src/shared/domain/game-labels.ts` (helpers such as `abilityName`, `rarityLabel`, `slotLabel`, `propLabel`, `setName`, `formatItemDisplay`). UI must not render raw `AbilityDef.name` / catalog PT labels without going through helpers when `Lang` matters.
5. **User-entered hero names** are never auto-translated.

## Portuguese chrome quality

1. PT UI chrome (buttons, metrics, guides, tips, import dialog) should read as **natural PT-BR**, concept-level — not word-for-word EN calques.
2. **Do not rename official in-game ability or house names** in PT to invent marketing aliases.
3. Prefer a glossary of recurring terms (uptime → tempo ativo, etc.) and reuse it consistently. Bare EN leftovers in PT must be listed with rationale or rewritten.

## EN copy quality

Prefer community-usable English for abilities/effects — not machine-literal calques. Keep effect numbers aligned with modeled `AbilityEffect` math.
