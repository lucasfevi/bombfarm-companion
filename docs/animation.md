# Animation

**Status:** reference (durable) · **Source:** Motion Accordion/Collapsible + planner Tabs IA + Tooltip (2026-07-24)

`Accordion.Panel` / `Collapsible.Panel` (`src/shared/design-system/accordion/accordion-panel.tsx`, `collapsible/collapsible-panel.tsx`) animate open/close via [`motion`](https://motion.dev) (`motion/react`), not a plain CSS transition on Base UI's `--*-panel-height` var. Planner workspace tabs (`src/shared/design-system/tabs/`) follow [Animate UI animate/tabs](https://animate-ui.com/docs/primitives/animate/tabs): horizontal slide + auto-height shell, inactive fade, spring highlight under the active trigger. Tooltips (`src/shared/design-system/tooltip/`) follow [Animate UI Base UI tooltip](https://animate-ui.com/docs/components/base/tooltip): Motion spring scale enter/exit on the popup. Each primitive is a directory (one file per part + a namespace `index.ts`) — see [`design-system.md`](design-system.md#compound-namespace-file-layout-w6).

## Rules

1. **Check [animate-ui.com](https://animate-ui.com) first.** WHEN building or redesigning an animated Base UI (or Radix) primitive THEN look up the matching component under `docs/primitives/base/*` (or `/radix/*`) before hand-rolling. It is a shadcn-style *copy-paste* distribution (`npx shadcn@latest add @animate-ui/primitives-base-<name>`) built specifically for `@base-ui` + Motion — real, working, MIT-licensed source, not a black-box dependency. Fetch its registry JSON directly if the docs site's code tab won't render (`https://animate-ui.com/r/primitives-base-<name>.json` returns the raw file contents).
2. **Disclosure (Accordion/Collapsible): mask-reveal + slide, not spring physics.** Animating `height: 0 → 'auto'` while an animated `--mask-stop` custom property drives a `mask-image: linear-gradient(black var(--mask-stop), transparent var(--mask-stop))`, so content fades out right at the growing/shrinking edge instead of being hard-clipped by `overflow: hidden`, plus a small slide (`y`). A flat `overflow-hidden` clip always leaves a hard edge no matter how long the duration or how fancy the easing curve — tuning duration/easing alone will not close that gap. See `maskRevealStyle` in `src/shared/lib/mask-reveal.ts`.
3. **`AnimatePresence` + conditionally-rendered panel, not `keepMounted` + CSS-detected transition.** Render the panel as `{open && <BaseCollapsible.Panel keepMounted hidden={false} render={<motion.div exit={...} />}>}` inside `<AnimatePresence>`. Do **not** rely on Base UI's own default unmount timing once Motion owns the animation: Base UI decides when to unmount / apply `hidden` (`display: none`) by detecting a **real CSS `transition-duration`** on the element (`getAnimationType()`); Motion animates via the Web Animations API instead, so Base UI would otherwise hide the panel the instant `open` flips, before Motion's exit animation gets a chance to play. `keepMounted` + explicit `hidden={false}` on the Base UI `Panel` neutralize that.
4. **Read `open`/per-item-open via `useContext`, never only inside the `render` callback.** Base UI's `render={(props, state) => ...}` callback receives a fresh, correct `state.open` on every call — but a `motion.div`'s `animate` prop built from a value that only exists inside that callback does not reliably trigger a Motion update (confirmed empirically). Track `open` as a real `useState`/`useContext` value in the wrapping component instead so `Panel` re-renders through React's normal hook mechanism.
5. **`MotionConfig reducedMotion="user"` wraps every `Root`.** Motion does **not** auto-respect `prefers-reduced-motion` the way the old `motion-safe:` Tailwind variant did. Wrap `Collapsible.Root` / `Accordion.Root` / `Tabs.Root` / `Tooltip.Root`'s children in `<MotionConfig reducedMotion="user">` so every nested `motion.*` degrades to near-instant automatically.
6. **Tabs: Animate UI animate/tabs.** Use the [animate/tabs](https://animate-ui.com/docs/primitives/animate/tabs) pattern — all panes mounted in a horizontal track (`x: activeIndex * -100%`), outer shell height animated to the active pane, inactive panes faded (`opacity: 0`) with `overflow: clip` on the shell. Do **not** blur inactive panes — CSS `filter` paints outside overflow and bleeds into the active stage. Spring highlight on the trigger. Do not fall back to Base UI Tabs for the planner stage.
7. **`transition-duration` differs by scope.** Nested disclosure rows (Effective-stats ledger, ~350–400ms) should feel snappier than tab panel transitions (~280ms ease-out). Don't apply one duration everywhere.
8. **Tab status: Tooltip, not in-flow banner — for the active hero's own trust/setup state.** WHEN a tab has trust/setup issues for the hero currently loaded THEN show a soft/warn **dot** on the tab and put the title + issue list in a DS `Tooltip` on hover/focus of that tab (Animate UI spring scale). Do **not** mount an in-panel banner that animates height and shifts content (CLS). Do not leave a global page-level *setup* banner. Which tabs soft/warn (and Account never) is owned by [`architecture.md`](architecture.md) + `src/shared/domain/planner-tab-status.ts`. This governs per-tab/per-hero chrome only — see the permitted exception below for roster-scoped advice.
   **Permitted exception — roster-scoped advice.** A tab dot can only speak for the hero currently loaded; advice about heroes *other than the active one* (e.g. "N other heroes could gain from a points reset") has no per-tab home to live in. A single DS `Banner` above the tab stage is allowed for that case, and only that case — `ResetAdviceRosterBanner` (`src/features/planner/components/reset-advice-roster-banner.tsx`, driven by `selectHeroesWithResetAdvice`) is the concrete, reviewed instance. It mounts and unmounts with the roster-wide reset-gate list, so it does shift the stage below it when it appears/disappears — that is an accepted, deliberate cost for discoverability of a cross-roster signal, not an oversight. **Still forbidden:** in-panel/in-tab banners for the *active* hero's own trust/setup state, and any global page-level *setup* banner — those keep using the dot + Tooltip pattern above.

## Anti-patterns

| Avoid | Prefer |
| --- | --- |
| Tuning `duration`/`ease` on a plain `overflow-hidden` height transition to chase "smoothness" | Mask-gradient reveal (rule 2) |
| `render={(props, state) => <motion.div animate={{...state.open...}} />}` reading `state.open` only inside the callback | `useContext`/`useState`-sourced `open` (rule 4) |
| Assuming Motion respects OS reduced-motion automatically | `<MotionConfig reducedMotion="user">` at the `Root` (rule 5) |
| Collapsed-preview siblings that exit-animate while a panel enters | Tabs (or synchronous unmount) — do not revive `Collapsible.Summary` exit animations |
| In-tab/in-panel status banners for the *active* hero's own state that grow/shrink layout | Tab dot + Tooltip (rule 8 — roster-scoped advice about other heroes is the sole exception, same rule) |
